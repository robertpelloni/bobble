# OmniCore Changelog

Document every adjustment. Track a single, global version string/date/build number sourced from a single text file (like VERSION.md) rather than hardcoding it into application logic.

- 1.13.1:
  - Probe all is real: run_bridge_probe now executes MultipathRouter::probe_and_recover_circuits against open/half-open circuits in the shared registry and reports each recovery (or honestly reports that none needed probing), instead of only logging that a probe was sent.
- 1.13.0:
  - Routing metrics now persist across sends: execute_routing_profile reuses the router stored at engine init instead of building a fresh BridgeRegistry per message (which discarded circuit/latency metrics every send). New Diagnose button in Bridges runs BridgeHealthMonitor over the accumulated metrics (MultipathRouter::registry accessor added), showing attempts, latency, circuit state, and anomalies per bridge; never-attempted bridges honestly report CandidateStarvation.
- 1.12.0:
  - Backup cipher upgraded to real AEAD: ZeroKnowledgeBackup now encrypts chunks with ChaCha20-Poly1305 (SHA-256 key derivation, deterministic per-chunk nonces, real SHA-256 chunk checksums — the checksum field previously held an FNV hash). Wrong-key and tamper restores fail at the AEAD tag; empty backups round-trip as one chunk. The XOR proof of concept is gone.
- 1.11.0:
  - Backup and QR pairing in the Security panel: Create backup snapshots contacts/messages/profile via ZeroKnowledgeBackup, Verify backup restores and checksum-verifies it in memory, and QR payload shows the omnicore://identity pairing payload. Also corrected the engine backup manifest, which claimed ChaCha20-Poly1305 while the implementation is a rolling-key XOR proof of concept — now honestly labeled in the manifest, UI, and tooltips.
- 1.10.0:
  - Offline outbox wired: failed sends queue in OutboxManager (OUTBOX_QUEUED) instead of dying; the Engine panel shows the real queued count and a Retry outbox button re-runs ready messages through the active routing profile, appending and persisting successes (OUTBOX_RETRY_OK). Failures requeue with exponential backoff and drop after 5 attempts (OUTBOX_DROPPED), all visible in Activity.
- 1.9.0:
  - Federation persistence: group channels (members, causal event history, active bridge, handovers) are serialized to the SQLCipher key_store after every group mutation (create, add member, post, handover) and restored on launch (FEDERATION_RESTORED in Activity). New engine FederationManager::insert_channel supports snapshot restore. Covered by test_federation_snapshot_roundtrip.
- 1.8.0:
  - Bridge handover in the dashboard: each group channel card has a target-bridge picker and Migrate button. Migration builds a FederatedChannelBridgeHandover (old bridge becomes fallback, causal history preserved), signs it, and applies it via FederationManager::handover_channel_bridge; logged as BRIDGE_HANDOVER. The engine signature scheme is simulated and is labeled as such.
- 1.7.1:
  - Group members: FederatedChannel::add_member (idempotent, advances causal clock) plus add_channel_member desktop command and a member picker in the Groups panel, so posts can broadcast to real members instead of only the local user.
  - Fixed mobile package-lock desync (npm ci EUSAGE: mime 1.7.0 vs 1.6.0) caused by a global version-string replace rewriting dependency versions; locks regenerated and verified with npm ci --dry-run. Version bumps are now surgical (root fields only). This also fixes the red Mobile job on the v1.7.0 CI run.
- 1.7.0:

Router is now shared between daemon and group posts.
